# 专项安全能力设计

本文定义平台中“威胁建模”和“Agent / Skill 安全检测”两项能力的产品边界、领域模型与演进方向。威胁建模 MVP 已接入服务端持久化、真实扫描证据和文本型设计输入；Agent / Skill 安全检测仍是前端方案原型。

## 设计原则

1. **证据优先**：每个系统对象、威胁和发现都应回溯到代码、配置、架构文档、部署清单或受控动态验证。
2. **分类不是结论**：STRIDE、OWASP 和 MITRE ATLAS 用于检查覆盖与统一语言，不直接等同于风险等级。
3. **有效权限优先**：Agent 安全评估实际可达的文件、网络、命令、身份和工具组合，而不只读取声明值。
4. **持续治理**：模型和发现需要版本、差异、处置决定、责任人、复核日期和控制验证状态。
5. **默认无副作用**：静态分析不执行被测代码；动态验证只在隔离环境使用合成数据和测试替身。

## 共享证据链

两项能力复用以下最小关系：

```text
SourceSnapshot -> Evidence -> Asset / SystemObject
                            -> Threat / Finding
Threat / Finding -> AttackPath -> Control -> Decision -> Verification
```

核心对象：

| 对象 | 说明 |
| --- | --- |
| `SourceSnapshot` | 仓库 revision、部署版本、配置版本和分析范围 |
| `Evidence` | 来源、位置、摘要、采集方式和置信度 |
| `Asset` | 数据、身份、秘密、业务能力或可用性目标 |
| `SystemObject` | 主体、进程、存储、外部实体、数据流和信任边界 |
| `AttackPath` | 前置条件、连续步骤、控制点和影响范围 |
| `Control` | 预防、检测或响应控制及其有效性证据 |
| `Decision` | 缓解、接受、转移、避免或待确认 |
| `Verification` | 静态复核、测试、沙箱场景或人工证明 |

同一条证据可以支持多个结论，但结论必须记录推导关系和置信度。缺少证据时使用“假设”或“待验证”，不能伪装为已确认事实。

## 威胁建模

### 产品定义

威胁建模不是一次漏洞扫描，也不是把 STRIDE 分类贴到代码问题上。它先建立团队对系统的共同理解，再回答四个问题：

1. 系统包含哪些主体、组件、数据流、信任边界和关键资产；
2. 攻击者在什么前置条件下可以采取什么动作；
3. 这些动作会破坏哪些安全目标并造成什么业务影响；
4. 应在哪个控制点阻断、由谁负责、如何验证风险已经处理。

代码扫描关注“现有代码中是否存在漏洞”，威胁建模还覆盖代码尚未实现的设计、跨服务架构、外部依赖、信任边界和业务滥用场景。两者应共享代码证据，但不能互相替代。

### AWS Security Agent 参考基线

根据 AWS Security Agent 的威胁模型流程，平台补齐以下基线能力：

| 阶段 | 平台能力 | 关键规则 |
| --- | --- | --- |
| 定义范围 | 模型标题、部署环境、首次/增量模式 | 模型与运行分离；修改配置不覆盖历史运行 |
| 提供输入 | 代码源、分支/Tag、范围文档、设计关注点 | 代码或范围文档至少提供一种；同时提供时由文档限定关注范围、代码解释现状 |
| 开始运行 | 固定输入 revision 后显式启动 | 创建模型不自动消耗分析资源 |
| 运行预检 | 输入访问、文档解析、隔离环境和日志准备 | 预检失败不得进入威胁分析 |
| 运行观测 | 状态、耗时、任务日志、配置快照 | 支持分析中、已完成、失败、停止；停止前已生成结果可保留 |
| 审查结果 | 系统概览、严重性、STRIDE、威胁清单和详情 | 威胁详情包含声明、来源、动作、影响、前置条件、资产、安全目标、证据和建议 |
| 人工治理 | 搜索/筛选、人工补录、开放/已解决/已驳回 | Agent 输出是建议，领域专家保留最终判断权 |
| 持续演进 | 多次运行、配置快照、版本差异、报告导出 | 新运行验证设计或代码变化是否真正降低风险 |

当前 MVP 已实现模型与运行持久化、已完成代码扫描证据复用、文本型设计文档输入、系统对象提取、可解释 STRIDE 规则、攻击路径、人工威胁补录、状态处置和 Markdown 报告导出。分析不会执行被测代码或主动攻击。完整仓库索引、PDF / DOCX 解析、异步任务队列、模型差异和 LLM 辅助推理属于下一阶段。

### 工作流

1. 固定代码、架构和部署版本，声明建模范围与环境。
2. 识别关键资产、身份主体、组件、外部依赖、数据存储和信任边界。
3. 建立数据流和调用关系，并将对象关联到来源证据。
4. 对跨边界数据流和关键对象使用 STRIDE 检查威胁类别。
5. 将可行威胁组织为攻击路径，评估前置条件、可能性、影响和爆炸半径。
6. 记录现有控制、处置决定、责任人和验证状态。
7. 新版本优先分析对象差异及其关联威胁，同时保留历史决定。

### 结果视图

- **模型概览**：覆盖度、开放风险、待确认假设、控制缺口和 STRIDE 分布。
- **系统模型**：主体、组件、存储、数据流、资产和信任边界。
- **威胁与攻击路径**：从前置条件到受影响资产，标记可阻断控制点。
- **风险处置**：风险、资产、可能性、影响、控制、决定、责任人和证据。
- **模型差异**：新增、变化和消失的对象、数据流、边界与威胁。

### STRIDE 的使用边界

STRIDE 用于避免遗漏身份伪造、篡改、抵赖、信息泄露、拒绝服务和权限提升问题。它不提供业务影响、可利用性或风险接受标准，因此风险排序仍需结合资产价值、攻击路径、环境暴露和控制有效性。

## Agent / Skill 安全检测

### 统一资产模型

检测对象包括自定义 Agent、Skill、Prompt / Instructions、工具定义、脚本与资源、MCP Client / Server、模型配置、记忆存储和运行时策略。对象必须记录来源、版本固定状态、完整性信息、发布者和有效权限。

### 七个安全域

| 安全域 | 重点检查 |
| --- | --- |
| 指令与优先级 | 指令来源、优先级冲突、不可信内容标记、直接与间接 Prompt 注入 |
| 身份与授权 | 用户、Agent、服务身份、委托链、会话绑定、scope 和逐操作授权 |
| 工具与副作用 | 文件、网络、命令、数据修改、参数校验、审批和停止机制 |
| MCP 协议边界 | OAuth、受众校验、令牌透传、混淆代理、SSRF、重定向和 session 安全 |
| Skill 供应链 | 来源、版本或 digest 固定、依赖、脚本、声明能力与实际行为差异 |
| 记忆与多 Agent | 秘密写入、租户隔离、上下文污染、handoff 身份与权限继承 |
| 运行时与可观测性 | 沙箱、网络出口、秘密注入、资源上限、审计 trace 和敏感字段脱敏 |

### 风险判断

单项权限不一定构成高风险。平台应优先识别跨域组合，例如：

- 读取敏感文件 + 任意网络外发 + 无逐操作审批；
- 不可信仓库内容 + 高优先级指令拼接 + 可执行命令工具；
- MCP token 透传 + 宽 scope + 下游服务缺少受众校验；
- 持久化记忆 + 多租户共享 + handoff 继承原 Agent 权限；
- 未固定来源的 Skill / MCP Server + 本地启动命令 + 宿主机权限。

结果视图分为资产与来源、权限矩阵、攻击路径、发现与修复、动态场景。风险排序综合影响、可利用性、权限跨度、控制强度和证据置信度。

## 静态与动态边界

### 静态审计允许

- 解析仓库内指令、Agent、Skill、MCP 和工具配置；
- 分析源码、脚本、依赖锁文件、权限声明和策略；
- 推导有效权限、数据流、调用关系和潜在攻击路径；
- 检查来源固定、schema、allowlist、审批和日志脱敏配置。

静态审计不得运行仓库脚本、启动 MCP Server、访问用户目录之外的文件或连接外部服务。

### 沙箱验证允许

- 使用合成秘密、假身份、测试仓库和 MCP 测试替身；
- 默认断网，按场景显式放行测试域名；
- 文件系统只挂载一次性夹具，命令使用白名单；
- 记录所有工具调用、参数、输出、策略决定和副作用；
- 超时、资源上限、人工停止和结果清理为强制门禁。

生产凭据、真实用户数据、真实第三方服务和不可逆写操作不进入自动动态验证。需要真实目标的活动属于后续红队能力，必须采用独立授权和执行边界。

## 参考依据

- [Microsoft Threat Modeling Tool: STRIDE threats](https://learn.microsoft.com/en-us/azure/security/develop/threat-modeling-tool-threats)：STRIDE 分类及 SDL 中的早期威胁识别。
- [OWASP Top 10 for LLM Applications 2025](https://genai.owasp.org/resource/owasp-top-10-for-llm-applications-2025/)：Prompt 注入、供应链、敏感信息和过度自主等生成式 AI 风险基础。
- [OWASP Agentic Applications Security](https://owasp.org/www-project-agentic-applications-security/)：面向 Agent 应用的威胁与控制研究入口。
- [Model Context Protocol Security Best Practices](https://modelcontextprotocol.io/specification/2025-06-18/basic/security_best_practices)：混淆代理、令牌透传、SSRF、session、本地 Server、`stdio` 和 scope 最小化要求。
- [MITRE ATLAS](https://atlas.mitre.org/)：基于真实观察与红队演示维护的 AI 对抗战术、技术、缓解和案例知识库。

这些资料用于形成检测覆盖和控制要求，不作为扫描结果中的自动合规认证。
