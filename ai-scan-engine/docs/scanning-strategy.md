# 扫描依据与策略

本文档描述 AI Scan Engine 如何执行平台安全基线。唯一规范来源是 `BUILTIN_SKILL_ROOT` 指向的 `security-baseline-review/SKILL.md` 及 `references/sec-baseline.md`；引擎不再维护独立漏洞基线。`internal/analyzer/policy.go` 负责加载并注入该 skill，确定性规则位于 `internal/scanner/scanner.go`。

## 1. 扫描输入与边界

引擎只分析任务指定 Git ref 的浅克隆快照。文件清单先应用以下边界：

1. `scanDirectories` 限定扫描目录；为空时扫描整个仓库。
2. 默认跳过 `.git`、`node_modules`、`vendor`、`dist`、`build`。
3. `excludeDirectories` 和 `excludePatterns` 追加任务级排除项。
4. 仅保留源码、配置、依赖清单和构建脚本，忽略文档、媒体和其他非扫描输入。
5. 跳过二进制文件和超过 `MAX_FILE_BYTES` 的文件，并在报告 `coverage.notChecked` 中说明原因。
6. 内置规则和 AI 共用筛选后的完整文件清单。AI 原始源码使用约 75% 的 `AI_MODEL_CONTEXT_BYTES` 分批，其余预算用于跨文件索引证据；`AI_MODEL_MAX_BATCHES=0` 时处理全部批次，正数表示显式运维上限。

## 2. 安全基线来源

引擎启动时一次性加载平台同一份 skill，并把以下内容随每个源码批次作为系统策略提交：

1. `SKILL.md` 中的扫描原则、扫描流程、核心判定规则、严重级别和证据要求。
2. `references/sec-baseline.md` 中访问控制、数据安全、第三方组件、AI 安全、通用漏洞、编码约束和验收检查的完整定义。
3. 当前任务选择的检查类型与扫描等级，仅用于确定优先级和分析深度，不得覆盖基线中的强制禁止项。
4. 引擎批次输出契约，仅覆盖 skill 的完整报告序列化格式，不改变基线判定标准。

`SKILL.md` 或 `sec-baseline.md` 缺失、为空、不是普通文件或超过 2 MiB 时，AI analyzer 初始化失败，不会回退到内置的另一套规则。

## 3. 两阶段扫描

### 阶段 A：确定性预筛

当前内置规则用于发现可直接匹配的高风险信号：

| 规则 | 扫描依据 | 类型 | 默认严重性 |
| --- | --- | --- | --- |
| `SEC-SECRET-001` | 变量名包含 key/secret/password/token 且赋值为长度至少 8 的字符串 | 安全基线 7.2 敏感数据处理 | high |
| `SEC-KEY-002` | PEM/OpenSSH 私钥头 | 安全基线 7.2 敏感数据处理 | critical |
| `SEC-HASH-003` | 调用 MD5 或 SHA-1 | 安全基线 V06 敏感数据泄露 | medium |
| `SEC-EXEC-004` | exec/system/popen/Command 参数存在拼接或格式化 | 安全基线 V03 命令注入 | high |

这些规则是候选信号，不做跨函数数据流分析；其置信度固定为 medium。真实上下文判断由 AI 阶段完成。

### 阶段 B：AI 证据链分析

每个源码批次带原始文件路径和行号。引擎为 Go、Python、JavaScript 和 TypeScript 建立函数级索引：Go 使用 AST 提取函数与调用符号，Python 使用缩进边界提取同步/异步函数，JavaScript/TypeScript 提取函数声明、箭头函数、函数表达式和类方法。每批根据符号精确匹配和全文词项相关度，最多扩展 3 层、补入 8 个跨文件函数，且证据总量不得超过该批剩余上下文预算。

模型按 skill 定义的九步流程审计：确定范围、识别数据流、检查访问控制、检查注入与输出、检查敏感数据、检查依赖与配置、检查 AI 门禁、检查测试、生成发现。只能根据代码、配置、依赖清单、锁文件、测试和 CI 中可观察的证据下结论；仓库外审批等事项不得推断，批次模式下也不生成无法从源码定位的 `manual-review` 项。索引证据使用原始路径和行号，因此可作为 Finding 位置，但模型不得假设未提供的调用方、防护或动态分派行为。

同一根因只报告一次；无法定位到已提交文件和行号的猜测、代码风格问题及没有代码证据的结论不得进入结果。

## 4. 扫描等级

| 等级 | 策略 |
| --- | --- |
| `lite` | 只检查直接、单文件、高置信度的危险构造和明显数据流；不依赖跨文件假设。平台通常关闭此等级的 AI。 |
| `standard` | 检查直接及同批次跨文件数据流、校验正确性、认证授权、Secret 处理和常见业务绕过；必须存在可实践的利用路径。 |
| `release` | 在 standard 基础上检查多文件信任边界、认证授权一致性、状态机/工作流不变量、绕过路径、错误回退和安全配置，强调发布阻断问题。 |

## 5. 严重性与置信度

严重性直接采用 skill 的定义，按影响与利用条件评定：

- `critical`：未认证远程代码执行、大范围认证绕过或同等级系统性失陷。
- `high`：可实践的越权读写、提权、凭据失陷或受限代码执行。
- `medium`：需要显著权限、少见配置、用户交互，或影响范围有限。
- `low`：存在具体安全影响，但有很强的缓解条件；不用于一般加固建议。

置信度按证据完整度评定：

- `high`：完整 source-to-sink 链，或直接危险构造，且已检查相关防护。
- `medium`：证据较强，但依赖一个明确写出的环境前置条件。
- `low`：源码有具体不安全行为，但可利用性依赖一个明确的未知条件。

## 6. 结果准入控制

模型输出不是直接信任的。引擎执行以下准入控制：

1. 必须是单个严格 JSON 对象，未知字段或缺失字段会使当前任务失败并重试。
2. `severity` 和 `confidence` 必须使用受控枚举。
3. 每条发现必须包含证据、影响、修复和验证方法。
4. 每个文件路径和行号必须真实存在于已提交给该批次的源码中；虚构位置会拒绝整个批次。
5. 相同规则、主位置、行号和标题生成稳定 ID，并在跨批次结果中去重。
6. AI 请求失败不会静默降级为“扫描成功”，任务由消息系统重试。

## 7. 当前限制

- Go、Python、JavaScript 和 TypeScript 可通过函数级索引补充跨批次证据，但当前是有界符号/全文扩展，不是完整污点图。
- Go 接口动态分派、Python 反射/猴子补丁/动态导入，以及 JavaScript/TypeScript 动态属性、回调注册和运行时模块加载可能无法静态解析；此类关系只能通过全文相关度降级召回，不能据此直接生成高置信度结论。
- 其他语言仍只能关联原始批次内可见内容。
- 内置规则仅 4 条，不应被视为完整 SAST 规则集。
- 引擎不执行依赖漏洞数据库查询、动态测试或运行时验证。
- Skill 在引擎启动时加载；基线文件更新后需要重启引擎。
