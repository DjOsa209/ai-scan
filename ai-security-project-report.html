Executive Summary

执行摘要

01
项目已经从单点代码审查工具，演进为覆盖开发现场、集中管理与异步全量扫描的完整产品体系。

不是再增加一套安全工具，而是建立一条可进入研发日常、可被组织治理的代码安全工作流。

开发者通过 IDE 插件完成代码变更增量扫描；团队通过平台发起仓库级全量扫描。轻量、标准与 Release 三级模式分别匹配演示验证、日常使用和上线前全面审查，最终统一生成符合传音内部治理要求的标准化报告。

对业务在发布前暴露高风险问题，降低返工与事故处置成本。
对研发IDE 增量扫描与平台全量扫描按场景协同，任务进度可实时同步查看。
对管理通过积分控制全集团使用时的并发量，并统一管理优先级、队列、模型与报告。

Security by Design

安全不是附加项

06
项目在数据、凭据、网络、模型、任务和审计六个方向设置边界，避免安全工具本身成为风险源。

DATA

最小化源码范围

源码快照只保留代码、依赖清单、容器 / IaC 与安全配置；排除文档、媒体、构建产物及二进制文件。

KEY

凭据分层保护

服务端仅保存用户接入密钥哈希；模型密钥使用 AES-256-GCM 加密；插件凭据进入 VS Code SecretStorage。

NET

远程内容网络约束

Remote Skill 仅接受 HTTPS，拒绝 URL 凭据、私网、Loopback 与 Link-local，并限制重定向及内容大小。

AI

模型输出不盲信

源码作为不可信数据；严格解析结构化 JSON；仅接受已提交文件与真实行号，减少提示注入和幻觉结果。

IAM

身份与所有权校验

平台任务身份只从服务端会话读取；插件按个人接入密钥识别；服务端校验任务所有权与状态转换。

LOG

关键动作完整留痕

任务创建、阶段更新与报告保存进入任务日志；Credit 变更形成账本流水，支持后续审计与追责。

RPT

内部治理报告统一

不同入口和扫描模式最终收敛到统一报告要求，确保漏洞证据、等级、研判、修复与审计信息符合传音内部治理规范。

风险发现前移率价值指标

在开发 / 合并前发现的有效高危问题，占全部有效高危问题的比例。

前移发现数 ÷ 全部有效高危数
有效漏洞确认率质量指标

经人工确认有效的发现占已研判发现的比例，并按规则与模型版本拆分。

确认有效数 ÷ 已研判发现数
高危平均修复周期效率指标

从发现到确认修复的平均时间，区分业务线、项目和发布阶段。

Σ（修复时间 - 发现时间）÷ 已修复高危数
扫描覆盖率采用指标

约定周期内完成安全扫描的活跃项目，占应纳入项目总量的比例。

已覆盖活跃项目数 ÷ 应覆盖项目数
单位有效发现成本经营指标

模型、计算与运营成本除以有效发现数，用于比较扫描模式与模型配置。

周期总成本 ÷ 确认有效发现数
平台任务成功率稳定指标

剔除用户主动取消后，成功生成可用报告的任务比例，并跟踪 P95 耗时。

成功任务数 ÷ 可执行任务数
